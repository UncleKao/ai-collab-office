# 遠端座位

先完成本機手動模式，再設定遠端。這份公開版不提供任何預設主機、帳號、SSH 金鑰或模型登入。

1. 為工作者準備 Linux 帳號、Python 3.11 以上及自己已登入的供應商 CLI。
2. 在該帳號可寫入的位置建立 `adapter` 目錄，把同一版本的 `office*.py`、`owner_proxy.py` 與範例設定放進去。不要同步中樞的 `data`、`secrets` 或模型認證。
3. 中樞帳號設定自己的 SSH 別名，先人工核對主機金鑰並以正常 SSH 登入。adapter 會強制 `BatchMode` 及 `StrictHostKeyChecking`。
4. 在中樞的 `workers.<識別碼>` 填入 `host`（SSH 別名）、`home`（遠端帳號家目錄）、`hostname`（目標的實際 hostname），及 `remote_dir`（其下須有 `adapter`）。這些欄位皆填自己的值。
5. 在遠端 `adapter/office-config.json` 填入同一工作者的座位資料、實際 `cli`、模型與 `automation: true`。遠端會比對家目錄與 hostname，錯誤即拒絕；不能拿中樞的路徑猜遠端位置。
6. 中樞亦填妥模型並啟用自動協作，再以小型工作測試新輪、續輪、工具提交和回傳檔案。

只傳本輪固定工作單、核准的來源快照與允許的成果。工具設定、原生 stdout／stderr、SSH 及模型認證不在回傳清單。符號連結、路徑越界、過量檔案或雜湊不符會拒絕傳輸。

遠端座位的本次公開版驗收限命令與傳輸邊界測試，沒有替測試者驗證真實 SSH、供應商登入或每種 CLI 版本。正式步驟回呼需讓遠端工作者能連到中樞自己的受保護入口；跨主機前請先核對網址和來源限制，回呼失敗不可當作步驟成功。
